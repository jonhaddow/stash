# Decisions

- **Replaces Readkit, Instapaper and Inoreader** (October 2026): one app, its own D1 database (not much data), for one person.
- **Two tabs, Later and Feeds** (October 2026): in Readkit, moving between the Inoreader and Instapaper sides took 4 or 5 taps. Here it's one.
- **Swipes, not buttons** (October 2026, replacing per-row buttons): in Feeds, swipe right marks an entry read (again: unread) and swipe left saves it to Later (again: takes it out; saved ones say "In Later"). In Later, swipe right archives, with Undo. Opening a link never archives it. What a swipe will do shows under the row as it slides, turning amber past the point where letting go does it. First tried buttons, since Readkit's swipes were hard to remember, but the buttons took room and swipes are quicker.
- **Links open the original page; no article extraction** (October 2026): Jon reads on the site (or, later, in the Reddit/HN apps). Also keeps the Worker well inside the free plan's CPU.
- **Thumbnails beside titles** (October 2026), in Feeds, Later and the archive: from the feed for entries, from the page's `og:image` for saved links (one saved from Feeds keeps its entry's). Only the URL is stored (https only) and the image loads from its own site, with no proxy. YouTube videos without one use the video's own thumbnail; rows without one, or whose image fails to load, show just the title.
- **YouTube videos play in the app** (October 2026): tapping one opens YouTube's embedded player (youtube-nocookie.com) over the list, so Jon stays in Stash; closing it stops the video, and a button opens it on YouTube instead. Other video sites still open their page.
- **Articles and videos are filtered apart**, on both tabs: different reading sessions. Decided by the link's site (`kind.ts`: YouTube, Vimeo and so on).
- **Feeds have read/unread, but nothing to tick off** (October 2026): opening an entry marks it read; unread ones are bold with a dot. The list shows unread entries by default (Jon's call): turning off the Unread chip shows read ones too, and with none left it says "All caught up." rather than falling back to everything. One swiped or opened read stays in place until the list reloads, so it can be swiped back. Entries are never removed. "Mark all read" is there if wanted, and stops at when the page loaded. A feed added in the app starts with entries older than a week read, so adding one doesn't flood the list.
- **Feeds are a separate list, not a river to triage**: Save copies an entry to Later; Later doesn't empty the feed.
- **Folders one level deep** (YouTube channels, blogs, Reddit), made while adding or editing a feed. They organise feeds in Settings only: the Feeds tab is one list, with no folder filters (Jon didn't use them; October 2026).
- **Archiving goes to a hidden archive** (Settings → Archive), not deleted; it'll also hold the Instapaper history.
- **Share sheet through an iOS Shortcut** (October 2026): iOS doesn't let home-screen web apps receive shares (no Web Share Target). The Shortcut posts the URL to `/api/save` with a token made in Settings (only its hash is stored; making a new one replaces it). JSON only, since SvelteKit's CSRF check refuses outside form posts.
- **Polling on the free plan** (October 2026): a cron every 5 minutes fetches the 5 feeds fetched longest ago, if not fetched in the last 30 minutes. Requests are conditional (ETag/Last-Modified), so unchanged feeds cost almost nothing. Waiting on the network doesn't count towards the ~10 ms CPU limit; parsing does, so feeds are parsed with regexes rather than an XML library. With more than about 25 feeds, each one is fetched less often than every 30 minutes; Workers Paid ($5/month) is the fix if that ever matters.
- **Sync log per feed**: every fetch (status, HTTP code, entries added, error, time), kept 30 days.
- **Reddit through its signed-in API** (October 2026): Reddit's public `.rss` is rate-limited per address, and Cloudflare's addresses are shared with every other Worker, so about 2 in 3 requests got 429s (one feed per run and retrying on the next run helped, but only by luck). Jon's existing Reddit app (app-only sign-in, no Reddit login) gets its own quota of 1,000 requests per 10 minutes. Feeds are still stored as their `.rss` URLs (subreddit links go straight to `/r/<name>/.rss`); `reddit.ts` sends those requests to `oauth.reddit.com` and hands the listing back as Atom with the same ids and links as Reddit's own feed, so nothing else changed and nothing was seen twice. Without the secrets (local development), `.rss` as before. The one-Reddit-feed-per-run and retry-a-429 rules stay, as a backstop. Turned down: fetching Reddit every 3 hours (fewer tries, not better ones), fetching it from the laptop (only when it's on).
- **Its own look**: Manrope, warm paper and ink, deep amber for actions and unread. Plants' floating tab bar. Follows the device's light or dark setting.
- **No push notifications** in v1.
- **Unread count on the app icon** (October 2026): the Badging API, set from the layout's unread count whenever the app is open or comes back to the front. iOS shows it only once notifications are allowed (a button in Settings). It doesn't update while the app is closed: that would need Web Push from the cron, and iOS doesn't allow silent pushes (each one must show a notification).
- **Imports are one-off scripts**, not a Settings page (October 2026): `scripts/import-opml.ts` writes SQL for `wrangler d1 execute`. Imported feeds start with everything read (Jon's call): their first fetch marks all existing entries read, so only new ones show as unread.
